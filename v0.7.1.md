## 0. Preámbulo operativo

Deprocast V3 es un sistema **local-first** de captura → extracción hermética → validación humana → memoria operativa. El núcleo verificado en 0.6 materializa el ciclo:

```
INPUT (audio) → VAULT + SQLite → PIPELINE (STT → LLM) → ADUANA (HITL) → VALIDADA
```

La transición 0.7 no redefine el kernel: lo **re-expone** como Centro de Mando (Trinchera), integra el CRM semántico (personas/proyectos/propuestas) y alinea la superficie de módulos (Castillo · Campamento · Trinchera · Pondering · Calendario · Captura Triad) sobre el mismo pipeline.

| Capa | 0.6 verificado | 0.7 en transición |
|------|----------------|-------------------|
| Captura | Zona franca (audio `.m4a` / `.mp3` / `.ogg`) | Captura Triad omnívora (audio · texto · visión) |
| Sink semántico | Notebook `Trinchera` (seed SQLite) | Trinchera = HUD + Hilo Diario |
| HITL | Aduana (quántomos + tareas) | Aduana + aprobación de entidades |
| Memoria | `entries` / `quantomos` / `pending_tasks` / `validated_file_metadata` | + `persons` / `projects` / `entity_*` / `embeddings` (Mnemosyne) cableados |
| Superficie UI | `franca` · `aduana` · `validada` | Mapa de módulos V3 sobre stages actuales |

**Leyenda de madurez**

| Símbolo | Significado |
|---------|-------------|

### DIM III — Ingesta y Captura Triad `[OK]` audio · `[→0.7]` omnívora

**Superficie actual (0.6):** *Zona franca* (`FreeZone`).

Contrato UX verificado:

1. Dropzone / file picker múltiple.
2. Extensiones aceptadas: `.m4a` · `.mp3` · `.ogg` (o `audio/*`).
3. Lista de selección con quitar individual.
4. Cola visible (`queued` / `processing`) con polling ~4 s.
5. Acción única **Procesar** = ingest HTTP + encolado de pipeline.
6. Feedback mono: status line + badges de estado.

**Captura Triad (visión 0.7)** — tres canales de entrada hacia el mismo notebook sink:

| Canal | Input | Estado |
|-------|-------|--------|
| A — Audio | Voice Memos / grabaciones de caminata | `[OK]` |
| T — Texto | Nota rápida / paste / Hilo Diario | `[UX-GAP]` |
| V — Visión | OCR / cuaderno (Cohere Vision previsto en `.env.example`) | `[UX-GAP]` · modelo `COHERE_VISION_MODEL` declarado |

**Latencia de captura (medida conceptual 0.6):**

| Fase | Comportamiento | Latencia percibida |
|------|----------------|--------------------|
| Upload vault | Sync: multer memoria → `vault/{entryId}/` + row `queued` | Baja (I/O local) |
| Encolado pipeline | Fire-and-forget; HTTP responde al aceptar | Baja |
| STT Deepgram | Bloqueante por entrada; ADTS chunkeado si > ~55 s | Media–alta (red + duración audio) |
| Extracción Cohere | + throttle `COHERE_REQUEST_DELAY_MS` (default 2000 ms) | Media |
| Aduana visible | Polling App ~4 s / CustomsPanel ~5 s | Hasta ~5 s post-`pending_review` |

Diseño de latencia: **captura nunca espera el pipeline**. La Zona franca libera al operador; la Aduana aparece cuando hay propuestas.

### DIM IV — Señal sensorial y atribución de origen `[OK]`

Invisible en UI salvo el campo `timestamp_exact` en Aduana, pero define la **verdad temporal** del Hilo Diario.

Prioridad de origen (`originAttribution`):

```
filename  >  transcript  >  metadata/mtime  >  upload_now
```

Patrones de filename tipificados (Voice Memos ES), p. ej. `3 ago, 14.18_.m4a` → ISO UTC.

En Aduana el operador puede corregir `timestamp_exact` (datetime-local) antes de aprobar. Esa corrección es la ancla del Hilo Diario futuro.

### DIM VI — CRM Semántico (UX) `[SCHEMA]` · `[SVC]` · `[→0.7]`

**Definición:** roster de *personas* y *proyectos* con propuestas `create` | `link`, evidencia textual y vínculos a entradas/quántomos.

Estado 0.6:

- Tablas: `persons`, `projects`, `entry_entities_raw`, `entity_proposals`, `entity_links`, `embeddings` — migradas.
- Matcher: `server/services/entityMatch.ts` → `createEntityProposalsFromEntry()` — `[SVC]` no llamado desde `POST /api/proposals/approve`.
- Pipeline Cohere devuelve `entities[]` pero **no persiste** en `entry_entities_raw` durante Station 3.
- Mnemosyne (`embeddings.ts`): upsert + cosine search — `[SVC]` no encolado post-aprobación.

**Flujo UX objetivo 0.7 (HITL entidades):**

```
Aduana aprueba entry
  → persist raw entities
  → create/link proposals (pending)
  → panel CRM: aprobar/rechazar entidad
  → persons/projects + entity_links
  → embedApprovedEntry / embedPerson / embedProject
```

Estados de propuesta de entidad:

| `status` | Significado |
|----------|-------------|
| `pending` | Esperando operador |
| `approved` | Roster actualizado + link |
| `rejected` | Descartada; sin roster |

Tipos de propuesta:

| `proposal_type` | Acción |
|-----------------|--------|
| `create` | Alta nueva persona/proyecto |
| `link` | Vínculo a entidad existente (match por nombre/alias normalizado) |

Kinds persona: `fisica` | `juridica` | `agrupacion`.  
Status proyecto: `activo` | `pausado` | `cerrado` | `emergente`.

### DIM VII — Flujo HITL / Aduana `[OK]`

**Superficie:** `CustomsPanel` — stage `aduana`.

Arquitectura visual:

```
┌─ toolbar: Aduana | rail multi-entry | Descartar | Aprobar ─┐
├──────────────────────────┬─────────────────────────────────┤
│ Transcripción literal    │ Procesado                       │
│  · Nombre (title)        │  · Quántomos (edit + OK/X)      │
│  · timestamp_exact       │  · Tareas sugeridas (edit+OK/X) │
│  · <pre> content_raw     │                                 │
└──────────────────────────┴─────────────────────────────────┘
```

Contrato HITL:

1. Entrada llega con `status = pending_review`.
2. App detecta pendientes (poll 4 s) y **auto-navega a Aduana** en el primer lote nuevo.
3. Operador edita título / timestamp / quántomos / tareas.
4. Ítems marcados `rejected` se eliminan (quántomos) o marcan `rejected` (tareas) al aprobar.
5. **Aprobar** → `approved` + snapshot `validated_file_metadata` + `recognized=1` en quántomos + tareas `accepted`.
6. **Descartar** → `rejected` a nivel entry (y tareas suggested → rejected).
7. Si no quedan pendientes → retorno a Zona franca.

Principio: **nada entra a memoria operativa sin firma humana**. El LLM propone; el operador dispone.

### DIM IX — Trinchera como Centro de Mando Unificado `[→0.7]`

**Definición arquitectónica:** la Trinchera no es solo un notebook; es la **consola diaria** donde convergen captura, cola, señales HITL y lectura del día.

#### 9.1 Hilo Diario

Secuencia cronológica de entradas del día (clave: `timestamp_exact`, no `created_at` de upload), agrupadas por jornada local.

Fuente de verdad post-HITL: entries `approved` (+ opcionalmente cola del día). En 0.6, Validada ya ordena por `timestamp_exact DESC`; el Hilo Diario es la misma query con agrupación por fecha y densidad narrativa.

#### 9.2 Input omnívoro

Desde Trinchera, el operador no elige “módulo de captura”: elige **canal** (A/T/V). Todo cae en `notebook_id = Trinchera` salvo reasignación explícita futura.

Hoy: solo canal A desde Zona franca, siempre a Trinchera.

#### 9.3 HUD lateral

Propuesta de composición (0.7):

```
┌ Hilo Diario ──────────────┬ HUD ────────────┐
│ 09:14  Nota sobre…        │ COLA   n        │
│ 10:26  Caminata…          │ ADUANA n ← HITL │
│ 14:18  …                  │ HOY    n notes  │
│                           │ CRM    n props  │
│ [input omnívoro Triad]    │ W avg  hermetic │
└───────────────────────────┴─────────────────┘
```

Mapeo a 0.6:

| Widget HUD | Fuente API existente |
|------------|----------------------|
| COLA | `GET /api/entries/queued` |
| ADUANA | `GET /api/proposals/pending` |
| HOY / hilo | `GET /api/entries/validated` filtrado por día |
| CRM | — (falta ruta de `entity_proposals`) |

#### 9.4 Latencia de captura (contrato de producto)

- **T₀** drop/select → archivo en vault + row `queued` ≤ ~1 s típico local.
- **T₁** “Procesar” → pipeline aceptado; UI no bloquea otras vistas.
- **T₂** `pending_review` → Aduana auto-aparece (poll ≤ 4 s).
- Objetivo 0.7: indicador HUD de fase (`queued` → `processing` → `pending_review`) sin forzar stage switch agresivo si el operador está en Castillo/Campamento (`preferFreeZone`-like flag ya existe).

### DIM III — Pipeline de ingesta de fuentes `[OK]`

#### 3.1 Ruta HTTP

`POST /api/ingest/audio` · multipart field `files[]`

Por archivo:

1. UUID `entryId`.
2. Decode filename UTF-8 (latin1→utf8 multer).
3. Escribir vault.
4. `resolveOriginAttribution({ filename, uploadNow, defaultYear: 2026 })`.
5. INSERT `entries` (`source_type='audio'`, `status='queued'`, `notebook_id=Trinchera`).
6. Response: id, title provisional, timestamp_exact, origin_source.

#### 3.2 Disparo de pipeline

`POST /api/pipeline/run` `{ entryIds?: string[] }`

- Sin IDs → todas las `queued`.
- Cola in-process (single-flight `running`); drenaje serial.
- Status: `GET /api/pipeline/status`.

#### 3.3 Estaciones del pipeline (`processEntry`)

```
Station 1 — STT (Deepgram)
  · detect magic bytes (ADTS/mp4/mp3/ogg)
  · split ADTS si duración > DEEPGRAM_SYNC_MAX_SECONDS
  · punctuate + paragraphs + smart_format
  · stub si no key / fallo / vacío

Station 1b — Refine origin
  · filename > transcript > existing timestamp

Station 2 — Cohere extractFromTranscript
  · suggested_title (clamp 3–5 palabras)
  · quantomos[] · actions[] · entities[]
  · delay COHERE_REQUEST_DELAY_MS
  · mock si no key / error

Station 3 — Persist
  · UPDATE entry: content_raw, timestamp_exact, title, status=pending_review
  · INSERT quantomos (recognized=0)
  · INSERT pending_tasks (status=suggested)
  · [GAP] entities[] no se escriben en entry_entities_raw
```

# EJE C — INPUT | PROCESAMIENTO | OUTPUT

## Guía orientativa al operador

Esta sección describe **qué hace el usuario**, **qué hace el sistema** y **qué obtiene**, sin jargon de implementación innecesario.

---

### C.1 INPUT — qué entra al sistema

| Canal | Cómo | Qué se guarda inmediatamente |
|-------|------|------------------------------|
| **Audio** `[OK]` | Zona franca → arrastrar/elegir `.m4a` `.mp3` `.ogg` → **Procesar** | Archivo en vault + ficha en cola (`queued`) con fecha tentativa (suele salir del nombre del archivo) |
| **Texto** `[→0.7]` | (previsto) nota / paste en Trinchera | Entry `source_type=text` sin STT |
| **Visión** `[→0.7]` | (previsto) foto de cuaderno / OCR | Entry + texto OCR |

**Regla de oro del input:** subir no es validar. Subir solo **encola**. La verdad operativa nace en Aduana.

**Consejo de captura:** nombrar audios con fecha/hora legible (`3 ago, 14.18_.m4a`) mejora el Hilo Diario sin edición manual.

---

### C.2 PROCESAMIENTO — qué ocurre sin intervención

Tras **Procesar** (o re-disparo de cola):

```
1. TRANSCRIBIR   audio → texto (Deepgram; si falla, stub marcado)
2. FECHAR        refinar timestamp (nombre > habla en el audio > upload)
3. EXTRAER       Cohere propone:
                   · nombre corto (3–5 palabras)
                   · quántomos (ideas densas + peso + universo)
                   · tareas sugeridas
                   · entidades mencionadas (aún no visibles en UI)
4. PRESENTAR     status → pending_review → aparece Aduana
```

Indicadores que verás:

| Badge / vista | Significa |
|---------------|-----------|
| `queued` | Esperando pipeline |
| `processing` | STT/LLM en curso |
| Aduana en nav | Hay al menos una nota lista para revisar |
| `pending_review` | Lista para HITL |

No hace falta refrescar a mano: la UI hace polling. Si el pipeline falla, la entrada vuelve a `queued` para reintento.

### C.3 OUTPUT — qué sale y a dónde

#### Salida A — Validada (memoria operativa) `[OK]`

Al **Aprobar** en Aduana:

- La nota pasa a **Validada** (lista expandible).
- Quedan congelados: título asignado, fecha, nombre original del archivo, transcripción.
- Quántomos reconocidos + tareas aceptadas.
- Export: **Exportar todo** → JSON `deprocast-validada-YYYY-MM-DD.json`.

Al **Descartar**: la entrada no entra a Validada (`rejected`).

#### Salida B — Tareas accionables `[OK]`

Cada tarea aprobada es un compromiso operativo etiquetado (`tag`). Hoy viven ligadas a la nota validada; el Campamento 0.7 las elevará a board táctico.

#### Salida C — Quántomos / Pondering `[OK]` datos · `[UX-GAP]` módulo

Ideas atómicas con `hermetic_weight`. Las de mayor peso son candidatas naturales a Pondering (revisión profunda).

#### Salida D — CRM Semántico `[→0.7]`

Personas y proyectos mencionados → propuestas create/link → roster Castillo/Campamento + búsqueda semántica Mnemosyne.

#### Salida E — Calendario / Hilo `[parcial]`

Hoy: orden temporal en Validada.  
0.7: vista Calendario + Hilo Diario en Trinchera anclados a `timestamp_exact`.
